# Deploy to Render with Neon

The app runs as one Render web service: Fastify serves both the React frontend and `/api` endpoints. PostgreSQL remains on Neon.

## Render service settings

The root `render.yaml` defines the service in Singapore, the build and start commands, and `/api/health` as the health check. It uses Render's Free compute plan to avoid recurring compute charges during initial setup.

Set `DATABASE_URL` to the pooled connection string from Neon when Render prompts for the unsynced variable. `JWT_SECRET` is generated by Render. Do not copy `.env` into Render or commit its values.

Render Free web services sleep after 15 minutes without traffic and can take about a minute to start again. For daily POS use, upgrade the web service to the always-on Starter compute plan (currently about $7/month). The Render Hobby workspace itself has no monthly fee; compute and usage are billed separately. Review the current pricing and set a spend limit before enabling paid resources.

## Build and start

- Build: `npm ci && npm run build`
- Start: `npm start`
- Health check: `/api/health`

Render provides `PORT` automatically. The server uses that port in production and falls back to `API_PORT` locally.

## Source repository requirement

Render deploys application source from a connected Git provider repository or a container image. The current workspace has no Git repository or remote, so connect a private GitHub/GitLab/Bitbucket repository containing this project before creating the Render service from this Blueprint. Keep `.env` out of that repository.

## Verify deployment

Open `https://<render-domain>/api/health`; the expected response is `{"status":"ok","database":"connected"}`. Then verify login, POS, and order history. Keep Neon as the source of truth unless a separate database migration is planned.
